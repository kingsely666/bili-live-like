# B站直播间点赞助手

一个集成在哔哩哔哩直播间**原生点赞按钮**上的用户脚本。不额外占屏幕、不加悬浮球，左键点原生按钮顺手完成一批点赞，右键弹出紧凑设置面板。

> 每房间每日上限 300 赞（对应 B 站亲密度规则：每 30 赞 +1，每日 10 次）。脚本不会绕过这个限制。

## 功能

- **左键原生点赞按钮**：原生 +1 照旧，同时自动跑完一批点赞，不打断原有交互
- **右键同一按钮**：弹出紧贴按钮的紧凑面板，可调「每次数量」「间隔」、开关「自动点赞」
- **按直播间分别记忆**：每个房间的开关与参数独立保存，切房不会互相覆盖
- **进房自动点赞**：开启后进入直播间自动完成，当日已点过则跳过
- **当日统计**：显示全站点赞总数与房间数，点击展开逐房间明细（主播名 + 房间号 + 赞数）
- **配额与累计分开记**：重置只清本房配额进度，当日已点过的赞仍保留在统计里（重置后再点 300，总数继续累加到 600）
- **Win11 Fluent 风格**：Mica 亚克力材质，跟随系统深浅色，`prefers-reduced-motion` 下关闭动效
- **零文字外泄**：封闭 Shadow DOM + 只在顶层页面运行，不会把样式或文字漏到 B 站页面

## 安装

1. 给浏览器装一个用户脚本管理器：[Tampermonkey](https://www.tampermonkey.net/)（Chrome / Edge / Firefox / Safari 均有）
2. 安装脚本，两个地址任选（前者国内可直连）：
   - CDN：[bili-live-like.user.js](https://cdn.jsdelivr.net/gh/kingsely666/bili-live-like@main/bili-live-like.user.js)
   - GitHub：[raw.githubusercontent.com](https://raw.githubusercontent.com/kingsely666/bili-live-like/main/bili-live-like.user.js)
3. 打开任意直播间，脚本自动生效

> 装好后在 Tampermonkey 管理面板确认 `B站直播间点赞助手（手动版）` 已启用，版本号应为 `2.2.2`。

## 使用

| 操作 | 效果 |
| --- | --- |
| 左键点原生点赞按钮 | 原生点赞 +1，同时自动完成一批 |
| 右键点原生点赞按钮 | 打开/关闭设置面板 |
| 点面板统计行 | 展开/收起逐房间明细 |
| `Esc` 或点面板外 | 关闭面板 |

面板里的「自动点赞」开关按房间记忆：在 A 房打开，只对 A 房生效。

## 数据与隐私

所有配置和统计只写在浏览器的 `localStorage` 里，键名如下：

| 键 | 内容 |
| --- | --- |
| `wb-bili-like-config` | 每个房间的开关、每次数量、间隔 |
| `wb-bili-like-records` | 当日各房间的配额进度与累计赞数，跨天自动归零 |
| `wb-bili-like-names` | 主播昵称缓存，避免反复请求 |

不采集、不上报任何数据，不发第三方请求，不含统计代码和广告。

## 常见问题

**点赞数没涨？**
打开控制台看脚本输出的房间解析与接口返回。常见原因是未登录、房间未开播，或达到当日上限。

**点赞后刷新页面数字又回去了？**
B 站点赞数本身有服务端同步延迟，脚本只负责提交请求，最终数值以服务端为准。

**提示「今日已达 300 赞上限」？**
每房间每日 300 赞，是 B 站亲密度规则对应的上限。面板里的「重置」只重置本地配额进度，不会改变服务端限制。

**换了直播间，设置或计数不对？**
设置和计数都按房间号分别存储，这是预期行为。跨房间的总数看面板里的「全站今日」。

**面板位置奇怪或被遮挡？**
脚本贴住原生按钮定位，空间不足时翻到按钮下方。若与其他脚本冲突，可先停用同类脚本再试。
